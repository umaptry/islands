# multilingual-e5-small. The Dockerfile installs it from PyTorch's CPU index, so
# we get the ~200MB CPU wheel rather than the ~2.5GB CUDA one. Keeping the same
# torch version as the build machine also keeps the embeddings numerically
# identical to the ones the frozen map was built from.
#
# What core/encoder.py's numpy implementation buys is narrower but still real:
# umap-learn never ships, and the frozen weights load from a plain .npz instead
# of a pickled nn.Module, so a future torch upgrade cannot silently move points.
