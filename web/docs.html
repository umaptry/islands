1. システム全体像

Architecture

「かさなり」は、一言の自己紹介文からその意味を数値化（448次元）し、ニューラルネットワークによって地図上の(x, y)座標を決定する Webアプリケーションです。似た話をしている人が自動的に近くに集まり、島や大陸を形成します。

💡
2つの動作モード：本番環境（Supabaseモード）ではブラウザが直接データベースにアクセスして高速描画。ローカル開発時はメモリ上でスタンドアローン稼働します。

2. ER図 & テーブル定義

7 Tables

データベース内のテーブル設計と各カラムの詳細定義です。すべてのテーブルでRLS（行レベルセキュリティ）が有効化されています。

erDiagram
    accounts ||--o{ posts : "1人のユーザーが0件以上の投稿を持つ"
    accounts ||--o{ reactions : "1人のユーザーが0件以上のリアクションを行う"
    accounts ||--o{ comments : "1人のユーザーが0件以上のコメントを書く"
    accounts ||--o{ notifications : "1人のユーザーが0件以上の通知を受け取る"
    accounts ||--o{ reports : "1人のユーザーが0件以上の通報を行う"

    posts ||--o{ reactions : "1つの投稿に0件以上のリアクションがつく"
    posts ||--o{ comments : "1つの投稿に0件以上のコメントがつく"
    posts ||--o{ notifications : "1つの投稿に関連して通知が発生する"
    posts ||--o{ reports : "1つの投稿に対して通報が寄せられる"

    comments ||--o{ notifications : "コメントが書かれると通知が発生する"
    comments ||--o{ reports : "コメントに対して通報が寄せられる"
🧑‍💼 accounts
RLS On
ユーザーの公開プロフィール。auth.users と連動。
  • id PK uuid
    Supabase Auth の user_id。退会時 CASCADE 削除。
  • display_name text (1-16)
    地図上に表示される名前。唯一の必須項目。
  • affiliation text (32)
    所属（大学・会社名など）。未設定可。
  • bio text (300)
    自己紹介文。投稿本文とは別物。
  • icon_id / avatar_path text
    絵文字番号またはアップロード画像パス。
📍 posts
Core Table
地図上の投稿。座標・エネルギー・ベクトルを保持。
  • id PK uuid
    投稿の一意識別子。
  • author_id FK uuid -> accounts
    投稿者ID。
  • body text (30-140)
    本文。この文章の意味から座標が計算される。
  • x, y double precision
    地図上の座標（0〜1000）。サーバーのみ計算。
  • vec, vec_c vector(448)
    意味ベクトル。ブラウザからは閲覧不可。
  • energy GEN real
    熱量 + (全リアクション数 + コメント数) × 5。
❤️ reactions
Composite PK
いいね・手伝えるかも・参加したいの記録。
  • post_id PKFK uuid -> posts
    対象の投稿ID。
  • actor_id PKFK uuid -> accounts
    リアクションしたユーザーID。
  • kind PK 'like'|'help'|'join'
    リアクションの種類。複合主キーで二重送信を防止。
💬 comments
RLS On
投稿に対するチャット・メッセージ。
  • id PK uuid
    コメントの一意識別子。
  • post_id FK uuid -> posts
    コメント先の投稿ID。
  • body text (1-500)
    コメント本文。
  • deleted_at timestamptz
    論理削除日時。NULLなら表示中。
🔔 notifications
Auto Created
リアクションやコメント発生時のユーザー通知。
  • recipient_id FK uuid -> accounts
    通知を受け取る投稿者。
  • actor_id FK uuid -> accounts
    リアクションした人。
  • read_at timestamptz
    既読日時。NULLなら未読バッジ表示。
🗺️ energy_cells
Terrain Map
20×20セルごとの広域エネルギーキャッシュ。
  • cell_x, cell_y PK integer
    セルの格子座標（0〜50）。
  • sum_energy, post_count real, integer
    セル内の合計エネルギーと投稿数。

3. 自動トリガー連鎖

Database Triggers

ユーザーが画面上でリアクションやコメントを行った際、データベース側で自動実行される処理フローです。

sequenceDiagram
    autonumber
    actor U as 👤 ユーザー
    participant R as 📋 reactions
    participant P as 📍 posts
    participant N as 🔔 notifications
    participant E as 🗺️ energy_cells

    U->>R: リアクション送信 (like)
    Note over R,P: トリガー: on_reaction_change
    R->>P: like_count を +1
    P->>P: energy を自動再計算
    R->>N: 相手への通知を自動作成
    Note over P,E: トリガー: on_post_energy_change
    P->>E: 該当セルの sum_energy を加算

6. セキュリティ & RLS ポリシー

Security

ブラウザが直接 Supabase にアクセスしても安全なのは、データベースの各テーブルに Row Level Security (RLS) が設定されているためです。

テーブル操作許可ルール (RLS)
accountsSELECT全ユーザー閲覧可（メールアドレスは含まない）
accountsINSERT/UPDATEauth.uid() = id（自分のアカウントのみ）
postsINSERT❌ クライアント不可（サーバーのみ）
postsUPDATEauth.uid() = author_id（自分の投稿のみ）
reactionsINSERT/DELETEauth.uid() = actor_id（自分のリアクションのみ）
notificationsSELECT/UPDATEauth.uid() = recipient_id（自分宛のみ）

7. 用語集

Glossary
用語解説
凍結エンコーダ448次元のベクトルを2次元座標(x, y)に圧縮する固定重みのニューラルネット。新しい人が投稿しても既存の点は1pxも動かない。
コサイン類似度2つのベクトルの向きの近さを測る指標（-1〜1）。1に近いほど意味が似ている。
似てる度コサイン類似度を一般ユーザー向けに 0〜100% のスコアに校正したもの。
エネルギー投稿の熱量 + リアクション数×5 で算出される値。周囲の地形の高さを決定する。
HNSW高次元ベクトルの近似最近傍探索インデックス。数万件の投稿からミリ秒で似ている人を見つけ出す。
