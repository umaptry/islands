この地図は、どうやって位置を決めているのか

あなたが書いた一文 → 数値 → 座標。途中で何が起きているかを最後まで追いかけます。

0全体の流れ

図0: 一方通行です。「他の人を見て調整する」工程はありません。年齢・性別・住んでいる場所は、どの段階でも登場しません。

1ことばを、2つの見方で数値にする

どの語を使ったか（64次元）— 文章を日本語解析器で単語に分け、珍しい語ほど重く数えます。「キャンプ」のように誰でも使う語より、「ブッシュクラフト」のような語のほうが強く効きます。

どんな意味か（384次元）— 言い回しが違っても意味が近ければ同じ方向を向くように、AIの埋め込みモデルが文章全体を数値にします。「焚き火を眺める」と「薪をくべて火を見る」は、共通の単語がなくても近づきます。

なぜ2つ必要か。意味だけを見ると、自己紹介は「〜が好きです」「〜をやっています」といった言い回しが似ているだけの文どうしが引き寄せ合ってしまいます。そこで、内容語だけを抜き出した「単語だけの文」も別に数値化し、生の文章と 0.35 : 0.65 で混ぜて、内容のほうに重心を置いています。

2位置が動かない理由

ふつうの次元圧縮（UMAP）は、点の位置そのものを直接調整します。だから誰か一人が増えるだけで、全員の位置がずれます。それでは「昨日いた場所」と「今日いる場所」が違ってしまい、地図として信用できません。

そこでこの地図では、448次元から座標を出す関数を一度だけ学習して、そのまま凍結しています。

図1: UMAPは「お手本を1枚描く先生」の役。実際に毎回座標を出すのは、そのお手本を再現するよう学習させて凍結したニューラルネット f です。
同じ文章を何度送っても、小数点の桁まで完全に同じ座標になります。あなたが増えても、先にいた人は1ピクセルも動きません。

3「似ている度」は、潰す前の448次元で測る

ここが少しややこしいところです。似ている度は、地図の上の距離からは計算していません。448次元のベクトルどうしの角度（コサイン類似度）から直接計算しています。

理由は、2次元まで潰した時点で近さの情報がかなり失われるからです。UMAPが守ろうとするのは「ご近所関係」であって「距離そのもの」ではありませんし、それを1枚の絵に潰す以上、こぼれる分は必ず出ます。このビルドでは本来のご近所のうち34%しか2次元に残っていないことが、ビルド時の検査値として記録されています（artifacts/seed_map.json の meta.gates.generalization）。

実際、カメラ・料理・プログラミング・運動の4ジャンル×3人で試すと、地図上の距離で並べた場合は12人中3人で「いちばん近い人」が別ジャンルの人になりました。448次元のまま測ると12人中12人が同じジャンルになります。だから、地図は「眺めるための絵」、似ている度は「潰す前の数字」と役割を分けています。

測る前に、みんなに共通する向きを引きます。埋め込みモデルには癖があって、日本語の自己紹介を入れるとどれも似た方向を向きます。土台1,000件の全ペア499,500組を測ると、意味のほうの数値は9割が幅0.058の狭い範囲に固まっていました。そこではほとんど何も区別できません。そこで、1,000件の平均の向き（＝「自己紹介という文章はだいたいこっちを向いている」という成分）を両者から引いてから角度を測ります。同じことを違う言葉で書いた2人が、話題は違うが言い回しが似ている2人より低く出る、という逆転がこれで直りました。

引き算をするのは比べる瞬間だけです。保存されている数値も、地図の座標も、1つも書き換わりません。

パーセントの目盛り。引き算のあとのコサインを、土台の1,000件から測った2点を基準に0〜100へ引き伸ばしています。

  • 0% … 1,000件からランダムに選んだ2人の下位5%と同じくらい（コサイン -0.116）
  • 100% … 1,000件の中で「その人にいちばん近い相手」の標準的な近さと同じくらい（コサイン 0.458）

実際に測るとこうなります。

  • 「焚き火を眺める」と「キャンプで焚き火を眺める、道具を揃える」 … 100%
  • 「焚き火を眺める」と「山で野営、薪を割る」（共通の単語ゼロ） … 97%
  • 「焚き火を眺める」と「フィルムカメラで街を撮る」 … 53%
  • 「焚き火を眺める」と「簿記二級の勉強」 … 39%
  • 「フィルムカメラ」と「簿記二級」 … 15%

2番目が大事なところです。共通の単語が1つもないのに97%。これが「言葉ではなく話していることで並べる」ということです。

「まわりの人」画面の同心円も同じ数字で並んでいます。内側にいるほど似ている度が高い人です。角度のほうは、全体マップ上であなたから見た実際の方角です。地図では遠くにいる人が内側の円にいることがありますが、それは不具合ではなく、上に書いた「2次元でこぼれた分」がそのまま見えている状態です。

4島と地形は、足し算でできている

座標が決まったあと、その上に地形が生えます。ここは元になった islands という プロトタイプの仕組みをそのまま持ってきた部分です。

投稿はそれぞれエネルギーを持ちます。

エネルギー = 熱量スライダー + （いいね + 手伝えるかも + 参加したい + メッセージ）× 5

そのエネルギーの大きさに応じたまるい丘（中心がいちばん高く、縁でゼロになる）を 地図の上に置き、重なったところは足し算します。合計の高さで地形が決まります。

図2: 一つの投稿の高さではなく、その地点の合計で地形が決まります。静かな投稿でも、隣り合えば緑になります。
ここが座標と噛み合っているところです。近い＝似た話をしているなので、 同じ話題の人が集まるほど地形が育ち、離れていた島が地続きになります。 盛り上がりが、そのまま大陸の形になります。

島の名前。丘が重なって1つながりになった投稿の集まりを、1つの島とみなします （AとB、BとCが重なっていれば、AとCが離れていても1つの大陸です）。名前は、その島に いる投稿から名詞を集めて「何人が使ったか × 珍しさ」で上位2語を選びます。

用意されたジャンルの一覧はありません。誰も投稿していない場所には名前が無く、 地図にも出ません。地図は名前のない海から始まって、人が来るたびにその人たちの 言葉で名前が増えていきます。

5共通していることば

2人の文章から取り出した内容語の重なりを、珍しい語から順に並べています。だから「音楽」より「電子工作」が先に出ます。珍しい語で一致しているほうが、偶然ではない共通点だからです。

共通の語が1つもないのに似ている度が高いことがあります。それは違う言葉で同じような話をしている、ということです。

6大事な注意 — 地図が見ているのは「文章」です

この地図はあなた自身を見ているのではなく、あなたが書いた1つの文章だけを見ています。同じ人でも、書く内容を変えれば別の場所に立ちます。

だから、まったく違う趣味の人が隣どうしになることがあります。たとえば「道具を自分で直す」という話をしていれば、自転車の人と革細工の人は近づきます。これは不具合ではなく、「何について語っているか」で並んでいるということです。

この地図が答えているのは「誰と誰が似た話をしているか」であって、「誰と誰が似た人間か」ではありません。1人1文という条件のもとでは、それが読み取れる情報の上限です。
